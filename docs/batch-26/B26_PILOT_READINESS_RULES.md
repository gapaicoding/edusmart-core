# EduSmart Batch 26 — Pilot Readiness Rules

Readiness is a live, read-only summary for one authorized school. It is not a production health check or a promise that the school has accepted a pilot. The server returns only stable codes, statuses, safe counts, route hints, and school display metadata.

## Status and aggregation

- `READY`: the checked prerequisite is present for the defined pilot path.
- `WARNING`: operator review is advisable, but the supported pilot path can continue.
- `BLOCKER`: a required setup or safe access prerequisite is absent.
- `MANUAL_FALLBACK`: external automation is unavailable and an approved manual/in-app workflow remains available.
- Overall precedence is `BLOCKER` → `WARNING` → `MANUAL_FALLBACK` → `READY`. No percentage score is calculated.

## Data and scope limits

- Counts are computed from canonical data when refreshed; no snapshots are stored.
- School ID is input only as a selector. The server reads the school through RLS and verifies `school.readiness.read` at that school scope before running aggregates.
- Finance, admissions, guardian, student, academic, teaching, and communication aggregates execute only when the actor has the corresponding scoped domain capability.
- Guardian link count joins active links to active enrollments in the selected school; it does not return guardian or student rows.
- No check edits data, provisions users, repairs links, assigns staff, issues invoices, or changes permissions.
- A `READY` technical result does not mean the school has accepted the pilot. Scope, training, support owners, and real-school validation remain external decisions.
